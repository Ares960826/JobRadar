# 同一招聘系统的名额分配

以“雇主系统 + 招聘届次/批次”定义限额组。机构名额与岗位名额是两层约束，不能简单相乘后任意分配。官网显示的研发部、城市和子公司名称不是独立名额的证据。

1. 查当届总公告、机构公告、岗位页及公开FAQ，记录官方链接、核查时间、机构上限、每机构岗位上限、志愿顺序、是否跨城市共享、变更/撤回/恢复规则和锁定节点。一般规则不能覆盖更具体的岗位规定。
2. 本人当届已用名额只能来自本人明确报告或准确对应当届的提交回执/账号记录。累计投递数、收藏、已准备材料、过往届次不能当成本届占用量。未知余额保持未知。
3. 在当前授权范围内比较同组高评级、核心城市的岗位。若有高价值机构尚未核查，列出覆盖缺口；不能将局部最高当作全系统最优。名额分配必须同时满足机构数和每机构岗位数限制。
4. 先提出供本人选择的组合与备选，说明同机构替代、跨机构机会成本和证据不确定性；不因截止紧迫自动消耗名额。期限仍决定岗位能否申请，但不是占用稀缺名额的优先依据。
5. 已过期岗位不能进入可投递组合。若本人接受为了更匹配岗位放弃临期机会，记录选择；AI不自行替用户放弃、不试投、不撤回、不改志愿以测试规则。

央国企和银行常见的情形：同一集团或公司允许跨地区、跨岗位类型投递多个岗位，但设总数上限，有时还按机构或地区再分层。上限决定优先级：例如只能投 1 个时，集中投该限额组里最适合的那个岗位，其余作为备选列出。第一轮录入该雇主时就要查这条规则并写入 `quota_note`；第二轮从它出发核实，并把同组岗位放在一起比较。查不到时写“未核到”和已查页面，不猜数字。

每个限额组在“机构投递限额”（quotas）表中各写一行，填写限额规则、机构上限、每机构岗位上限、跨城市规则、改报与撤回、官方依据和招聘批次。“已用及剩余名额”只依据本人报告填写；本人未报告时写“未知”。“本人决定”属于人工字段，Agent 不写。候选记录的“限额处理”可以摘要这些规则，但不能代替 quotas 表中的规则行。

示例（虚构）：某银行当届校招总公告明确最多 3 家招聘机构、每机构最多 2 岗；其软件开发中心公告明确跨城市合计 2 岗；公开 FAQ 未核到撤回恢复规则。限额记录要写明核查日期和官方公告链接，未来批次必须重新核查。
