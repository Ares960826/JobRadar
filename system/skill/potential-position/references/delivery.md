# 第二轮表格交付

All record and view-column writes go through `position.py apply` (see SKILL.md); the rules
below are what `validate`/`guard` check plus the layout conventions they cannot check.

## 用户视图

- 固定公司及岗位名称，单一“公司｜岗位”首列或冻结至岗位列均可。
- 链接只保留“招聘入口”和“岗位直达链接”两个展示字段。“岗位来源”、独立“入口核查状态”和第三个补充入口不再出现在交付视图。来源及核查证据可留本地 `_support/`；既有远端审计字段可隐藏，无需破坏性删除。
- “招聘入口”是官方总入口/单位招聘入口；“岗位直达链接”合并链接与问题状态。已完整核到对应岗位：显示可点击链接，可用岗位名作为短标签。存在问题：同一个单元格显示具体问题，不伪造 URL、不填 `#` 或主页充数。
- 推荐飞书 `text(style=plain)` 富文本：已核链接使用 `[岗位名称](https://verified.example/...)`，问题使用普通文字。2026-09-20实测 URL 类型会把空目标文本自动补为 `http://问题文字`，CLI、原生 API 和原生编辑器均遇到此现象；不要重试这种坏写法。若其他版本确实支持空目标，需要回读及UI验证后才能用。字段转换前读取完整定义、保存快照并保留名称、数据和布局；不能只凭写入成功判断显示正确。
- **线索（LEAD）和未定位单岗的记录不得让用户空手而归**：“岗位直达链接”单元格必须同时给出①可点击的已核公告或官方入口链接，标签写明性质（官方/转载、批次公告/非单岗）；②一句话现状（待定位、需登录等）。链接只能取自已核来源；第三方转载或聚合页必须在标签标明“非官方”，不得充当官方直链；拿不到任何已核链接时，写明已查过的入口和障碍。“岗位来源”字段不在用户视图，不能把唯一的链接藏在那里。
- 没有单岗链接时，定位说明写最短点击路径、精确岗位名称及障碍；不要把相关子岗位或旧届次链接直接显示成原岗位已完成。
- 其他字段按需要保留：评级与依据、城市、紧迫性、截止日期及可信度、本人行动、编号、核查状态与缺口、限额处理、用户决定和备注。别把核查过程扩展为越来越多的展示列。

## 布局与更新

首次交付可建议“公司｜岗位、评级、岗位直达链接、定位说明、紧迫性、截止日期、招聘入口”等顺序。更新时必须以**实时读取的用户列序**为准，仅移除/合并当前要求的字段，不重放模板覆盖用户排序。
各视图分别读改写；列序不等于记录排序。不要随合并列操作改变记录评级、排序、筛选或用户新增字段。
同一表按 ID 串行 delta 更新，保留人工值；不删行表达淘汰。失败或回执不明时先回读，不盲目重放批量写入。

## 日期和验收

默认使用表自身时区的 TODAY() 等原生公式，避免 AI 逐日改评级。

截止时刻约定：“已核截止日”是日期时间字段。官网只写日期时，存为当日 `T12:00:00+08:00`，这个中午时刻只是排序用的占位，不是官方时刻。此时“日期可信度”必须写明“仅日期”，“截止说明”照录官网原话。官网写明时刻时（例如 24 时），按官方时刻存储，24:00 记作当日 `T23:59:00+08:00`，并在截止说明中注明原文。核对时，不能把 12:00 占位当成官方中午截止，也不能因此报告与官网“24 时”冲突。
排序键为 S→A→B→C→D、紧迫级、截止日、编号；辅助紧迫视图才以紧迫性为主。限额比较与核查门槛先于排序。
**已投递沉底（全局规则，适用于所有候选岗位视图，包括辅助紧迫视图）**：`application_tracking` 中按永久编号关联到有效投递状态（已投递及其后的笔试/面试/Offer 等，依据须为本人报告或提交回执）的岗位，无论评级和紧迫性多高，一律排在该视图记录顺序的最后；其内部仍按上述排序键。仅调整表格顺序，评级、依据、用户决定、本人备注等原始信息不改、不删行。实现：候选总表和集团岗位比较表各有公式字段“已投递排序（自动）”（未登记投递=0，其余=1，由 `投递状态` 引用跟踪表得出），所有带排序的候选视图和集团比较视图都以它升序为第一排序键；新建视图时照此设置，不得手工逐行移动。
空白、非法日期和过期日期独立处理。相对“今天”的本地快照要标日期，不能冒充实时提醒。

交付前核对：记录数和分页完整性、永久编号无重复、硬淘汰不在有效视图、人工字段未覆盖、用户列序保留、只有两类入口展示、链接/空目标问题文本可正确显示。对已改公式检查过去/今天/1/2/3/4/7/8天/空白/非法日期边界；紧迫排序编码为 0–3（剩余天数，0为今天）、4（4–7天）、5（8天及以上）、6（截止待核）、7（已过期）、8（博士后准备期不足 N 天，按已过期处理，N 为实例的 `postdoc_prep_days`）、9（已淘汰），与 `presentation.py` 的 `URGENCY` 一致。博士后导师合并表（`postdoc_mentors`）的紧迫公式先扣除 N 天准备期再分档（`urgency(..., prep_days=N)`），候选总表维持原规则；无变化不反复运行无关检查。
本地 HTML/CSV 如需保留，应从最新回读生成并遵循同样列序；不能用旧脚本恢复已隐藏的字段或过时状态。

## 统一工作台与投递后跟踪

用户的求职表集中在一个 Base 文件，候选、机构覆盖、限额与投递跟踪是内部数据表。不同视图共享记录，不为待核/已核复制同一岗位。既有人工列序不变，核查和限额字段就近插入；公司及岗位保持冻结。
参考第三方模板时只复用结构，不复制他人投递数据。投递跟踪通过永久编号及关联字段连接候选，保存投递状态、投递时间、下一次笔试/面试安排、状态依据和本人备注。记录“已投递”必须有本人报告或提交回执；材料准备完成不算已投递。未发生的日期、状态和Offer不得预填。
隐私边界不变：岗位和流程摘要可进入飞书，身份资料、简历正文/附件不随同步上传。第一轮本地历史池不因整理第二轮工作台而自动同步。

博士后导师表（`postdoc_mentors`，以导师为核心，并入原博士后科研岗表，旧 `postdocs` 表退役）：每位合作导师一行；没有写明导师的单位或公司科研岗、基金项目、机构入口、方向线索也在本表，“类型”字段区分，主列写单位或公司名；所有行与候选总表一样评级（S–D，只看契合）并填写学历要求、岗位直达链接，主列“导师｜课题组”写“姓名｜单位简称·院系·课题组”。字段：机会编号、证据层级（单选 1–4）、依托单位、地区、学院、研究方向、方向契合、在招证据（原文引文+日期）、声明日期、在招链接、导师主页、资助途径、申请方式、截止说明、排序参考截止日、核查缺口、关联博士后表、核查日期、准备期判断（自动）、用户决定、本人备注。默认视图“按证据层级”依次按证据层级、排序参考截止日、机会编号排序。资助途径只列有依据可挂靠的途径（同校项目、项目规则写明），每条带 JOB 编号；途径的截止日和准备期在本表的“准备期判断（自动）”里看。博士后科研岗表的“合作导师要求”写官方页面对是否须先联系导师、导师需提供什么（支持信、联合申请、学校提名）的原文概括，未核写“待核”。

## 名称与集团比较

- 公司及招聘机构名称必须脱离上下文仍能识别归属，如“某集团软件开发中心（上海）”；禁止仅写“软件开发中心”“数据中心”“上海分行”。岗位官方名称单独保留，展示首列使用完整公司及岗位。限额规则标题也必须包含所属集团/公司。
- 大集团比较使用同一 Base 内独立的“集团岗位比较”数据表，通过关联字段连接候选总表，并以公式引用名称、评级、城市、限额和核查缺口等事实；不要维护独立评级副本。每条比较记录只关联一个永久岗位编号。
- 不再创建“待核与条件缺口”视图；具体缺口保留在候选岗位记录中。集团比较已迁为独立表，不在候选总表里另建比较视图。

- 实测公式引用富文本链接会丢失 URL，仅剩标签。比较表的两个入口字段使用普通富文本，按永久编号从总表同步原始 Markdown 链接；更新总表链接时同步这些字段并回读核对，其余事实继续公式引用。

- 集团岗位比较表内部按“一家企业或集团一个 sheet（视图）”组织，视图直接用企业/集团名称命名（如“某集团”），并按“所属集团”精确筛选。企业或集团实际纳入比较时才新建对应视图，不预建空白企业视图。

## 学历要求必填

候选总表和各集团比较视图必须展示“学历要求”，默认紧邻综合评级。依据单岗条件及官方附件记录最低门槛（本科及以上、硕士及以上、明确要求博士等），保留“博士优先”等附加说明；不得把优先条件改成硬性要求。博士后单独明确是招聘岗位、在站或出站经历要求，不当作学历等级。单岗更严格条件优先于机构通用门槛；未知标待核实，不能按岗位名称推断。集团比较表从候选总表公式引用。
