# 工作流与使用方法

> 本文是给人看的说明。Agent 执行规则以两个 SKILL.md 为准：[jobradar](../system/skill/jobradar/SKILL.md) 和 [potential-position](../system/skill/potential-position/SKILL.md)。两者冲突时以 SKILL.md 为准。

JobRadar 的流程是：搜索 → 第一轮淘汰 → 第二轮择优 → 你选定编号 → 深入调查与材料准备 → 你亲自提交。第一轮保留只表示没有足够的淘汰证据，不表示资格已全部通过。

建立实例的步骤见 [templates/instance/README.md](../templates/instance/README.md)。

## 怎么用

1. 在 Agent 里说明要做的事。检索和初筛用 jobradar；择优、维护表格、交付或记录投递用 potential-position。说明检索范围或要更新的批次。
2. Agent 用当前宿主的搜索工具，按官网、结构化合集、其他来源的顺序获取证据。
3. 初筛结果保存为 `outputs/` 下的独立批次。后续更新按 JOB 编号保留你的手工记录。不要用删行表示淘汰。
4. 第二轮核查职责、资格、城市、截止日期、直达入口和投递限额。公开来源确认不了的关键条件会单独列出。
5. 你明确选定岗位编号后，才进入定制简历、补充调查和面试准备。

第二阶段有四种模式，开工时必须声明：

| 模式 | 能做什么 |
|---|---|
| `review` | 硬条件复核、评级和核实指定候选，更新或新建候选记录 |
| `maintain` | 只改你点名的字段或列，不搜索、不重新评级、不新增记录 |
| `deliver` | 按永久编号把已核实的候选增量写入飞书 |
| `track` | 只根据你本人的报告或回执记录投递状态 |

## 开始完整运行前

1. **飞书登录**：让 Agent 运行 `radar.py doctor`，看 `feishu_auth` 是否就绪。未就绪时在终端运行 `lark-cli auth login`。第二轮的 `preflight` 也会检查，未登录会直接拒绝。
2. **硬条件和职业画像**：写在实例的 `Profile/`。Agent 会直接读取这里的文件，所以只放你愿意给 Agent 看的内容。简历等其他个人文件要经过你自己的隐私工具或你的明确许可才能读取。`Profile/` 的原文不会写入飞书。
3. **浏览器**：很多招聘网站要渲染后才能读取。Agent 用完会关闭自己打开的标签页，管不到的标签页会告诉你。
4. **优先级和范围**：开始时说明先做什么。中途要加范围或改优先级，直接告诉 Agent，它会用 `amend` 记录你的原话，并在同一批次里继续。
5. **时区**：大陆招聘网站的时间按北京时间记录。

## 用工性质标注

岗位页上的“合同工”可能只是普通劳动合同，也可能是博士后之类的特殊身份，要看具体单位和公告。

- **已证实没有正式身份的**：官方原文明确写了劳务派遣、外包、不纳入编制或项目制聘用等，才按硬条件淘汰，并附原文和链接。只有“合同工”三个字或公告没提，都不算证实。
- **证实不了的**：不淘汰也不降级，在“核查缺口”写明待你本人判断，并附原文、链接和查过的页面。你判断之前，这类岗位不会进入“可供本人决策”。

这条规则只在你的硬条件要求正式身份时才有意义。

## 投递数量限制

很多大型雇主允许同一人投多个岗位，但限制总数，有的还按机构或地区分层。如果一家只能投 1 个，就要集中投最合适的那个。

- **第一轮**：每个批次第一次录入某个大陆雇主时，Agent 查当届公告和常见问题里的限额，并连同官方链接记录下来。查不到就写“未核到”和查过的页面，不猜数字。没有这一项的雇主（已淘汰的除外）过不了收尾。
- **第二轮**：Agent 再次核实，把同一限额组的岗位放在一起比较，先列最合适的，其余作为备选，由你决定投哪个。限额未核到的岗位不会标成“可供本人决策”。截止时间紧也不会自动占用名额。

## 长期关注清单

每年分批招募的项目，这一轮赶不上，下一轮仍可申请，不能当作过期就丢掉。

- 清单在实例的 `system/state/watchlist.json`，用 `radar.py watch` 维护。飞书里只在该岗位的“核查缺口”注明已挂起。
- 每条记录官方证据显示的周期、下一轮时间（官方公布、估计及依据，或未知）、复查日期、会随时间失效的资格条件和未核实的关键点。
- 第一轮的 `doctor`、`init` 和第二轮的 `preflight` 会列出到期条目。没有定时任务，所以只有你打开会话时才会提醒。
- 已截止但官方写明会周期招募的项目，仍要录入并登记，否则第一轮过不了收尾。
- 新一轮公告发布后，用新编号建记录，父记录指回原编号。只有你说不再关注，条目才会关闭。

## 博士后

如果你也在找博士后，可以在 `preferences.json` 设置 `postdoc_prep_days`（准备期天数，0 表示不设）。联系导师、写研究计划和准备推荐信都需要时间。

- **放在一张表**：博士后岗位、奖学金、资助项目和导师都放在 `postdoc_mentors` 表，用“类型”字段区分，编号与候选总表不重复。
- **准备期**：距官方截止不足设定天数的记录，紧迫性显示“准备期不足 N 天，按已过期处理”，排在后面，也不进紧急提醒，但评级和状态保留。周期性项目同时登记到长期关注清单。
- **以导师为核心搜索**：多数博士后途径都要先有合作导师，招聘帖只说明导师此刻有经费招人。搜索顺序是院校 → 相关院系 → 教师名单 → 逐位看在招证据 → 能挂靠的资助途径。
- **证据层级**：1 正式帖加主页声明，2 仅主页声明，3 仅正式招聘帖，4 潜在导师（方向契合但未见在招）。写明声明日期，太旧的声明按潜在导师算。1–3 档用 JOB 编号，4 档用 LEAD 线索号。
- **资助途径**：注明合作导师要求，如须先联系导师、导师要出什么材料。需要支持信的途径，联系导师的时间也算在准备期内。
- **联系导师由你来做**：Agent 可以在你点名后起草邮件，但不代发。
- **企业博士后**：企业工作站按普通岗位处理，放在候选总表，不计准备期。高校、科研院所和事业单位的博士后仍按上面的规则处理。

## 第二轮评级

- 先做硬条件检查。已确认违反硬条件的直接淘汰，移出有效候选，但保留永久编号、来源和原因。未知条件标待核，不算通过也不算违反。
- 评级只看职责、职业价值和与你的匹配，不看截止日期。S 极强匹配，A 强匹配，B 值得申请，C 补充，D 低优先级保留。弱匹配是低评级，不是淘汰。
- 评级、证据完整度、硬条件状态和紧迫性分开记录。具体岗位和公司或方向线索分开标识。
- 默认按 S→A→B→C→D 排序，同评级内按紧迫性和参考截止日排序。特别紧急分为今天截止、剩 1 天、剩 2 天、剩 3 天；4–7 天为一般紧急，8 天及以上为常规；日期已过提示核实在招状态；空白或无效日期标待核，不当作紧急。
- 紧迫性由飞书公式计算，不会让 AI 随时间改评级。官网只写日期时，“已核截止日”里的 12:00 只是排序占位，“日期可信度”应注明“仅日期”，官方原文写在“截止说明”。

## 飞书工作台

工作台分为候选岗位、博士后导师、机构核查、投递限额、投递跟踪和集团岗位比较。表和视图的 ID 写在实例的 `system/config/feishu-workbench.json`，Agent 不会写入其他多维表格。

- 交付表只展示“招聘入口”和“岗位直达链接”两类入口。不能用总入口、相关子岗位或旧招聘页冒充已核实的直达链接，未解决的问题直接写在直达列。
- 更新前读取你最新的列序，不会用模板覆盖手工排序。
- 待核缺口留在岗位记录的“核查缺口”。“本人行动”只放你自己的选择和材料准备。
- 投递跟踪只按你本人的报告或回执更新。

## 多个宿主

- **注册**：实例里的 `.agents/skills/`（Codex、OpenCode）和 `.claude/skills/`（Claude Code）都链接到同一份源码，不改任何宿主的私有配置。工具差异见 [hosts.md](../system/skill/jobradar/references/hosts.md)。
- **靠脚本把关**：第一轮由 `radar.py` 检查预算、字段、硬条件哈希、编号和初筛结果；第二轮由 `position.py` 检查模式、写入前的改动、写入后的人工字段与列序。
- **收尾回执**：每次工作结束，Agent 必须给出 closeout 回执。没有回执或回执未通过，就不算完成。
- **自动排队**：两个阶段共用一把锁，后来的 Agent 会自己等待并说明锁在谁手里。只有占锁的 Agent 看起来已停止工作时才会来问你，强制释放也只能由你批准。
- **初始快照**：第二轮每次开工都要重新拍一张飞书快照。换一天或换模式时最好开新批次，免得收尾时把前一次的修改算进来。
- **永久编号**：由本地台账 `system/state/skill-ids.json` 发放，同时对照各批次和最近的飞书快照里的最大编号，台账丢失也不会重复发号。

## 不可越过的边界

AI 不执行最终提交、发送申请邮件、上传简历或任何会触发申请的“下一步”。登录、验证码、声明签署和最终申请都由你本人操作。代理只在具体受阻的网站上尝试，而且要能限定到该网站，不启用全局代理。
